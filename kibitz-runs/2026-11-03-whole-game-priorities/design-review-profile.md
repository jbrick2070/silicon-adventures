# Macintosh adventure design review
This is a design decision, not permission to implement. Read local source files. No game or sound sessions, save operations, external user contacts or product edits. Use the five required review headings. Keep each review to roughly 350 words and group duplicate defects. Cite source symbols or archive IDs. Address a ranked whole-game roadmap and the first slice that an implementer could test. Prioritise one decision that would change what a player sees or chooses. A new persistent state model, mechanics rewrite, JDK dependency or extra instrumentation needs evidence of necessity. No new recommendations about provider tooling.
