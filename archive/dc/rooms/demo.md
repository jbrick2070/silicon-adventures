Offsets below are hexadecimal; CODE offsets exclude the four-byte segment header. `PROVEN` describes bytes or instructions read directly; interpretations are marked separately.

- **PROVEN — identity:** The disk image opened with `machfs` contains `Castle Preferences` resource `DEMO` ID 8127 named `Default`, 1,062 bytes. Its SHA-256 is `69e0e2212478cb0f6cc2e8d00735e576c5f81b85ff1fbb890ec57e448814a2a4` (the resource bytes, not the fork). CODE 1 `$242e–$2468` requests a named `DEMO`, reads its first two big-endian words and stores a pointer to byte `$4`. CODE 1 `$2604–$2612` supplies the Pascal string `Default` from `$2642`.
- **PROVEN — header:** Bytes `$0–$1` are `$041e` (1054); bytes `$2–$3` are `$0000`. The first word is stored as the playback bound and the second as a separate game parameter at CODE 1 `$245a–$2468`. The semantic meaning of the second word is **null**; CODE 1 `$2062–$207a` shows that the value 11 has a special effect.
- **PROVEN — stream:** Byte `$4` begins the command stream. In CODE 2 `$310e–$312a`, the reader increments a cursor and checks it against the first header word before reading; CODE 2 `$3226–$322e` turns a byte with its high bit set into a delay count using `byte & $7f`. For example `$84` means a count of 4 and `$ff` means 127. CODE 2 `$3108–$310a` decrements the counter before fetching more input. A delay is a count of calls to this update path; its wall-clock duration is **null**.
- **PROVEN — commands:** CODE 2 `$312c–$3156` masks a nonnegative command with `$fc`, then dispatches. At `$315a–$31aa`, pairs `$04/$06`, `$08/$0a`, `$0c/$0e`, `$10/$12` respectively clear/set the two signed directional fields to -8, +8, -8, +8. At `$31ae–$31d4`, `$14` clears input bit 1 and `$16/$17` sets it and consumes a following byte, combining the opcode low bit and that byte into a word. At `$31d8–$3222`, `$18/$1a`, `$1c/$1e`, `$20/$22` respectively clear/set input bits 0, 2 and 3. These changes match the recorder at CODE 2 `$2e24–$306c`.

The names of the three remaining buttons are **null** pending correlation with the key definitions and hero code.

On this resource the final read byte is `$ff` at resource offset `$420`; `$65` at `$421` and four bytes `$75 $85 $89 $ad` at `$422–$425` lie beyond that read boundary. Their purpose is **null**.
